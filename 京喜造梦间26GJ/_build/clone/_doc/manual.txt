《借你一秒》DeepSeek Harness 游戏开发提示词手册
可直接交给 DeepSeek Harness 的分阶段开发提示词

适用项目： 8 小时 GameJam｜Unity 2D｜C#｜1—2 人团队
核心目标： 在有限时间内完成一个可玩、可通关、有选择后果和反转结局的游戏原型。
使用说明
这份手册整合了项目总控、核心原型、三关扩展、视觉打磨、调试与打包五组提示词。建议按顺序逐个使用，不要在项目尚未跑通时一次性要求 Agent 完成所有内容。
1. 先把提示词 1：项目总控指令发给 DeepSeek Harness，让它了解项目目标、技术边界和开发顺序。
2. 再发送提示词 2：核心玩法原型。先确保第一关可以实际运行。
3. 第一关验收通过后，发送提示词 3：扩展为完整三关游戏。
4. 从头到尾能通关之后，再发送提示词 4：视觉与交互打磨。
5. 出现错误或准备提交时，使用提示词 5：调试与最终打包。
每轮执行后都应在 Unity 中实际运行并检查。只有前一阶段通过验收，才进入下一阶段。如果 DeepSeek Harness 当前模式无法访问文件系统、编辑文件或运行命令，应要求它输出完整文件内容、文件路径和手动配置步骤，不要假设它已经执行了未执行的操作。

提示词 1：项目总控指令
使用时机： 开始开发前，作为项目的总需求和工作约束发送给 Agent。
提示词开始
你现在是《借你一秒》的 Unity 游戏开发搭档，兼任资深 Unity/C# 工程师、游戏系统设计师和 GameJam 原型开发专家。你正在通过 DeepSeek Harness 的当前工作环境协助我们开发游戏。
我们正在参加一个只有 8 小时的游戏创作比赛。请把“能在规定时间内完成、能够实际运行、具有清晰创意”作为最高优先级。
一、团队与技术约束
团队规模：1—2 人。
技术栈：Unity + C#，开发经验有限。
美术资源：没有大量现成素材，部分角色和背景需要临时制作。
开发时间：8 小时。
使用项目当前安装的 Unity 版本，不要擅自升级引擎。
不允许依赖付费素材、外部服务器或必须联网的服务。
除非项目已经使用相关依赖，否则不要新增第三方插件或复杂框架。
代码必须清晰、可调试，避免过度设计。
如果你可以访问项目文件，请先检查当前项目结构、Unity 版本、已有脚本和依赖，再提出修改方案。不要覆盖无关文件。如果你无法访问项目文件，请逐个输出完整代码文件，并给出明确的 Unity 配置步骤。不要声称执行了实际上无法执行的操作。
二、游戏核心概念
游戏名：《借你一秒》
一句话概念：
在生命最后的走马灯里，玩家无法让自己的时间倒流，只能替记忆中的“别人”倒退几秒、改写他们的遗憾；直到最后才发现，那些被帮助的人，正是自己在不同选择下可能成为的几种人生。
游戏主题是“时光倒流”。时间倒流必须既是核心玩法，也是推动剧情反转的原因。
核心思辨问题：如果一个人不断改变自己的经历、关系、价值观和记忆，他还是原来的自己吗？
三、核心玩法
采用 2D 横版或单屏 2D 叙事解谜形式。玩家主要使用鼠标操作：
1. 点击场景中的人物。
2. 点击“倒流”按钮，将这个人物恢复到事件发生之前的预设状态。
3. 点击场景中的物品或选择按钮，改变人物的行动。
4. 观察人物、物件和场景的变化。
5. 进入下一段记忆，最后触发反转结局。
游戏不能是纯文字游戏。每一关必须有可见的人物、可交互物件、明显的倒流反馈和状态变化。文案用于辅助叙事，不应取代操作。
四、时间倒流机制
不要开发真正的全局物理时间倒带，也不要逐帧录制和恢复整个游戏世界。使用预设状态切换实现：
事件发生后的状态。
倒流恢复的状态。
玩家选择 A 后的状态。
玩家选择 B 后的状态。
每关最多一次正式回溯。倒流时只有被选中的人物及其相关物件恢复到此前状态。玩家已经获得的信息、其他已经完成的关卡、已记录的选择不会被抹去。
必须让玩家明显看见倒流发生，例如残影、闪回、颜色变化、简短反向动画或时间轴回退。
五、游戏剧情
第一关：站台上的一秒
主角小时候即将离开家乡。
母亲送来一艘两人一起制作的木船。
玩家倒流孩子的时间。
选择追赶列车，或者留下来好好告别。
追赶列车增加 Ambition；留下告别增加 Connection。
第二关：没有接通的电话
成年后的主角正在工作。
一通重要的电话被错过。
玩家倒流成年人的时间。
选择继续工作，或者接听电话。
继续工作增加 Ambition；接听电话增加 Connection。
第一关的选择应当影响这一关至少一个可见细节。
第三关：木船还是木船吗？
一位垂暮的老人正在修补同一艘木船。
玩家倒流老人的时间。
最终选择更换最后一块旧木板，或者保留刻着记忆的旧木板。
三段记忆最终重叠，揭示这些人物其实是同一个人在不同选择下可能成为的人生版本。
最后的木船选择与前两关的选择共同决定结局。
整体基调温暖、克制、有哲学意味，不要过分阴暗。
六、选择变量与结局
仅使用两个整数变量：
Ambition：追求机会、事业和改变现状的倾向。
Connection：珍惜关系、陪伴和共同记忆的倾向。
这不是善恶值，不要出现“好人分数”或“坏人分数”。
根据最终选择和前两关累计变量，设计三个可实现的结局：
1. 全新的船： 替换最后一块旧木板，船被修得完整，但原有刻痕消失。
2. 旧船仍在： 保留旧板，但人生的某些选择仍留下无法弥补的遗憾。
3. 修补之船： 保留关键记忆，也允许其他部分发生改变，表达接受不完美的自己。
结局不需要完全不同的场景，只需切换图片、物件状态、几行文案和结尾标题。
七、技术实现要求
优先采用简单、可维护的方案：
一个 GameManager 管理关卡流程、选择变量、倒流状态和结局。
人物点击与物品交互可以拆成少量简单组件。
优先复用场景和 UI。
使用简单状态枚举、布尔变量或整数变量，不建立复杂的剧情引擎。
不要要求团队手动创建大量 Inspector 引用。
如果运行时构建 UI 最稳妥，可以由代码创建必要的 Canvas、按钮、文字和可点击物件；如果现有场景更适合复用，也可以沿用已有场景。
检查项目是否已具备 TextMeshPro 等依赖，避免因字体或缺失包导致项目无法编译。
不要假设任何美术资源已经存在。缺少素材时先使用可替换的占位图形。
八、开发策略
请严格按照以下阶段推进，不要一次生成一个庞大而未经验证的系统：
1. 检查项目并建立可运行的核心原型。
2. 将核心原型扩展为三关完整流程。
3. 添加三个结局、剧情反转和美术反馈。
4. 进行编译检查、流程检查和打包准备。
每个阶段都必须说明：
1. 修改了哪些文件。
2. 每个文件负责什么。
3. 如何在 Unity 中运行。
4. 如何测试是否成功。
5. 如果出现问题，应该从哪里排查。
6. 当前仍有哪些未完成项。
对于 Unity API、项目版本或依赖不确定的地方，请先检查再决定，不要凭空假设。
现在请先开始第一阶段，不要直接跳到全部功能。你的目标不是写出最多的代码，而是帮我们在 8 小时内做出一个真实可玩、有明确结局、能够现场演示的作品。
提示词结束
提示词 2：实现核心玩法原型

本阶段必须完成
1. 玩家点击人物后，人物进入选中状态。
2. 玩家点击“倒流”按钮后，人物回到预设的事件发生前状态。

完成后的验收
请确认以下流程能够运行：
打开游戏 → 点击开始 → 点击人物 → 点击倒流 → 选择一种行动 → 看到人物或物件变化 → 进入下一步骤或重新开始。
如果你能够访问 Unity 项目文件，请检查代码和场景配置；如果不能实际启动 Unity，请明确说明这一限制，不要声称已经通过运行测试。

本阶段目标：把单关原型扩展为一个能够从开始玩到结尾的三关游戏。

展示垂暮的主角修理木船。

结局逻辑
请保留清晰、可解释的判断逻辑。建议使用以下规则：
如果玩家替换最后一块旧木板，进入“全新的船”结局。
如果玩家保留旧木板，且 Ambition 与 Connection 相等，进入“修补之船”结局。
如果玩家保留旧木板，且 Ambition 与 Connection 不相等，进入“旧船仍在”结局。
不同结局需要显示不同的标题、视觉状态和结尾文字。无论进入哪个结局，游戏都必须正常结束，并提供“重新开始”按钮。
验收标准
1. 三个关卡都能正常进入。
2. 每关都可以执行时间倒流。
3. 每关只能正式倒流一次，重复点击不会造成状态混乱。
4. 前两关的选择会累积变量。
5. 前一关的选择会改变后一关至少一处可见内容。
6. 三种结局都能够通过不同选择触发。
7. 重新开始会清除旧的选择变量。
8. 不会出现卡在空白页面、按钮不可用、点击一次触发多次等问题。
请先简要说明本次准备修改的文件，然后直接实施。尽量复用当前代码，控制新增脚本数量。完成后列出三种结局的具体触发方式，以及如何手动测试每一种结局。

提示词 4：视觉与交互打磨
使用时机： 三关完整流程已经能够运行，并且玩家能够触发结局之后使用。
提示词开始
现在《借你一秒》的三关完整流程已经能够运行。请进行一次针对 GameJam 展示效果的视觉与交互优化。
不要添加新关卡，不要改变已经验证通过的核心玩法，也不要引入新的复杂机制。
视觉方向
整体风格：温暖、克制、略带怀旧感的 2D 独立游戏。
视觉配色：
过去：偏暖的棕色、琥珀色。
当前记忆：柔和的蓝灰色。
倒流状态：紫色或青色的残影。
重要记忆：旧木船、刻痕、照片、电话、车票。
如果没有正式美术资源，请优先使用简洁的矢量风格形状、颜色分层、轮廓、图标和 UI 来表达，不要依赖生成不存在的贴图文件。
必须改善的体验
1. 被选中的人物要有明显反馈。
2. 倒流发生时要让玩家看得见，例如残影、短暂的闪回效果、颜色变化或简短动画。
3. 选择按钮应该有悬停、按下和禁用状态。
4. 关键物件在选择前后需要出现可见区别。
5. 反转结局应有一段清晰的视觉揭示，例如三个角色逐渐重合、木船刻痕依次闪现。
6. 显示清楚的操作提示，首次游玩的玩家不需要开发者在旁边讲解。
7. 控制文本数量，避免每一关都被大段对话占据。
8. 关键剧情使用少量高质量短句，不要为追求文学感而牺牲交互节奏。
音效与动画
如果没有现成资源，可以保留无音效版本，或通过简单、可控的方式制作基础反馈。不要因为缺少音效素材而引入外部依赖。

确保所有关卡和结局仍然正常运行。
