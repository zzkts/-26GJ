## 1. 怎么运行 / 怎么验证

### 在编辑器里玩

Unity Hub 打开本工程 → 打开 `Assets/Scenes/Main.unity` → Play。
场景里只有一个空物体（`GameBootstrap`），画布、三章舞台、人物、道具、按钮、文字**全部由代码在运行时生成**，
所以不会出现预制体引用丢失的问题。菜单栏有「错过了那一秒」三个菜单项。

### 一条命令跑完整验证（改完代码立刻跑）

```powershell
$sb = [ScriptBlock]::Create((Get-Content '<工程>\_build\verify\rebuild-and-check.ps1' -Raw -Encoding UTF8))
& $sb                       # 编译 + 内核断言 + 打包 + 运行时自检
& $sb -SkipBuild            # 只跑编译 + 内核断言（几秒钟）
```

它做四件事：

| 步骤 | 内容 |
|---|---|
| 1 | 用真实 `UnityEngine` 程序集**全量编译** `Assets/Scripts`（任何语法/类型错误都会失败） |
| 2 | 编译并运行**脱离引擎的内核校验程序**：71 组断言 |
| 3 | `Unity.exe -batchmode` 打包 Windows 播放器 |
| 4 | 用 `-cuoguo-selfcheck` 启动播放器，在**真实运行时**里自动把整局游戏跑一遍：39 组断言 |

> **编辑器开着也能打包。** 无头打包需要独占工程锁，如果 Unity 编辑器正开着主工程，
> 脚本会自动改用一个独立的构建目录（默认 `D:\gj_build`，短 ASCII 路径）来打包，再把产物拷回
> `Build/Windows`。首次会重建 Library（约 1.5 分钟），之后都有缓存。
> 想强制在工程本体里打包（需要先关掉编辑器）：加 `-InPlace`。

### 手动打包

```powershell
& 'D:\Unity6\Editor\Unity.exe' -batchmode -quit -nographics -projectPath '<工程>' `
```

## 2. 旧版去哪了（重要）

工程里原本是**旧版《借你一秒》**（点击选人 → 借他一秒按钮 → 四态切换 → 三结局）。
策划案明确说明旧版的三档规则已被连续时间轴取代，两套设计的目标完全不同，因此本次是重写。

旧版代码**一行没删**，整体移到了：

```
Assets/Legacy借你一秒~/          ← 文件夹名以 ~ 结尾，Unity 会完全忽略它（不编译、不导入）
    Scripts/{Core,View}/
    Editor/
```

想恢复旧版：把 `Assets/Legacy借你一秒~/Scripts` 改回 `Assets/Scripts`（先把新版挪走）即可，文件完好无损。

### 顺带修掉的一个真实隐患

`ProjectSettings.asset` 里 `activeInputHandler` 原本是 `1`（**只启用新输入系统**）。
在这种设置下，旧版代码创建的 `StandaloneInputModule` **收不到任何鼠标事件**——
也就是说旧版的界面按钮和点击在打包版本里大概率是点不动的（旧版没有在真机验过输入）。

现已改为 `2`（新旧都启用）。新版因此可以用 UGUI 事件 + `Input.GetMouseButton` 兜底，
滑块拖拽在打包版本里是真的能用鼠标抓的（第 5 节有射线检测断言为证）。

## 3. 新版架构

单场景、按章节根节点启用/隐藏。**规则全在不引用 UnityEngine 的 Core 里，所以能脱离引擎跑断言。**

```
Assets/
  Scenes/Main.unity          只有一个 GameBootstrap（入口）
  Scripts/
    GameBootstrap.cs         入口：摄像机 / EventSystem / GameManager
    Core/                    ← 刻意不引用 UnityEngine，可独立编译与断言
      TimelineModel.cs       关键帧、连续插值、TimelineCue、CueBoard、ChapterTimeline
      DebtModel.cs           最大回溯深度、债务计算、跨章继承、阈值档位
      StoryData.cs           三章的轨迹关键帧、线索阈值、文案、布景与滑块藏身处（改剧情只动这里）
      GameFlow.cs            阶段推进、借时、防卡关、唯一结局、重新开始
    View/                    ← 表现层
      GameManager.cs         唯一总控：输入 → Core → 画面，演出编排（含无头自检钩子）
      ChapterStage.cs        按 ChapterData 搭出一章舞台，并把轨迹绑到同名对象
      TimelineBinder.cs      把 TrackSample 套到 Transform 与 Tintable 上
      TimeSliderController.cs 世界内滑块的拖动、悬停、发现提示
      MemoryDecayController.cs 债务 → 损坏档位与阈值事件
      Tintable.cs            基色缓存 + 时间轴染色 × 褪色染色
      EndingSequence.cs      结局演出（闪回 → 归还 → 木船特写 → "他们都知道。"）
      DockArt.cs             占位美术：码头/木船/人物/罗盘/海图/纸船/刻字/三处滑块底座
      UiFactory.cs           UGUI 工厂（不用 TextMeshPro，用内置 LegacyRuntime.ttf）
      SoundKit.cs            运行时合成音频：主 BGM、倒带、线索、纸张、海浪、滑块轻响
      SelfCheckRunner.cs     无人值守运行时自检（-cuoguo-selfcheck）
  Editor/
    ProjectSetup.cs          生成入口场景 + 写 Build Settings
    BuildScript.cs           打包（含"一键生成场景并打包"）
```

### 时间轴是连续的，这是最容易做错的地方

`TimelinePosition` 是 0—1 的 **float**：1.0 = 现在，0.0 = 这段记忆最早的过去。
关键帧只是**程序内部的控制点**，玩家可以把滑块停在任意位置：

- 采样时找夹住 position 的相邻两帧做归一化插值，**不吸附到最近的帧**；
- 每帧可以把位置、旋转、缩放、颜色、透明度一起套上去；
- 松开鼠标后时间冻结，不自动播放（采样是无状态的）。

滑块是**世界内实体**，不是 HUD：三章分别藏在栏杆黄铜槽（第一章）、系船桩旧铜环（第二章）、
工作台黄铜轨道（第三章）。

### 债务怎么算

```
PastDepth             = 1 - TimelinePosition
MaxPastDepthReached   = 本章到过的最深程度，只增不减
ChapterDebt           = round(权重 × MaxPastDepthReached)     权重 30 / 30 / 40
GlobalDebt            = CommittedDebt + ChapterDebt           0—100，跨章继承
```

因此：**重复经过已探索区域不重复收费，向右拖回现在不退款，同一帧大幅拖动只按新深度算一次。**
三章都探到最早位置时正好 100。核心线索的 `DecayWeight` 很小（0.15—0.25），
所以画面被破坏到最严重的程度时，罗盘/刻字/海图/纸船**仍然看得清**。

### 一处**有意偏离**策划案，请确认

策划案第二章的时间表（0.82 出现 → 0.64 减速 → 0.46 停步 → 0.27 塞海图 → 0.12 远处停留 → 0.03 转身）
在时间方向上是**互相矛盾**的：全局规则是"0.0 = 最早的过去"，
但"塞海图"（0.27）必然发生在"站在远处停留"（0.12）**之前**，表里却把停留排在更深的位置。

作为主程序我的判断是：**策划案之所以是这个游戏，靠的就是"拖动时记忆在眼前真正倒退"**，
所以按全局规则做了**真正的时间倒序**——向左拖时他做过的事被一件件撤销：

```
1.00 已经走了（入口空）
0.90 正在转身离开，身影淡入
0.84 在远处站了很久——他来过，也停过
0.66 走向木船
0.58 把海图塞进船缝
0.50 塞完直起身
0.42 停步、抬手又放下（发现青年身边有个人）
0.22 退回入口方向
0.12 退到入口
0.00 站在入口，手里攥着海图
```

线索阈值与三条提示文案（"有人来过这里。" / "再看一眼。他为什么没有走近？" / 海图是他塞进船缝的）
完全沿用策划案。**如果你们更想要策划案表格里的字面顺序，改 `StoryData.cs` 里 `Track("Friend")` 的关键帧即可，不用碰其它代码。**

### 策划案里另一处自相矛盾：第一章的滑块藏在哪里

策划案对第一章滑块的描述有两处互相冲突：

- 第一部分第 2 条："滑块嵌入码头**栏杆**、系船桩或木船轨道"
- 第一章「当前画面」："时间滑块隐藏在**栏杆**一段看似普通的黄铜槽里"
- 第三部分第 4 节："位置分别为：第一章：**太阳** / 第二章：系船桩上的旧铜环 / 第三章：木船底部或工作台上的黄铜轨道"

我按**前两处**实现（藏进左侧码头栏杆的黄铜槽，坐标约 (−520, −183)）：一是两处都写的是"栏杆"，
二是"太阳"读起来像是早期草稿的残留（太阳本身就是天上的一枚圆形物件，不适合当可拖动轨道，
也和"看似普通的码头物件"这条设计原则冲突）。

**如果"太阳"才是你们要的**，改法很简单：`ScenarioData` 里第一章的
`SliderStyle = "railing"` 改成新增一个 `"sun"` 样式，`RailCenter` 指到天空，再在
`DockArt.BuildSliderRail` 里加一个 `"sun"` 分支画太阳即可——控制器、债务、时间轴都不用动。

### 已补齐的两处"当前画面"细节

初版漏了策划案第一章与第三章「当前画面」里明确写的两个视觉元素，现已补上，并做成**随时间轴变化**：

| 策划案原文 | 实现 |
|---|---|
| 第一章："木船停在前景，**船底有不自然的阴影**" | 船底压着一块由三块角度不一致的暗块叠出的阴影（88% 不透明度）。时间往回走时它逐渐退开（到最早处只剩 5%），**罗盘正是从它底下浮出来的** —— 这是第一章最重要的视觉伏笔 |
| 第三章："男人俯身修船，**工作灯只照亮木板**" | 船身中下部加了一团窄而暖的光池（50% → 85%），越往过去越亮，像是记忆慢慢对准了那处夹层 |

两条都进了断言（第 5、6 组），以后被改掉会立刻报错。

### 5.4 时间轴必须与场景在同一套基准上（第 17—19 组断言）

这是本项目最容易出错、而且肉眼不容易第一时间发现的一类问题，所以专门做成了断言。

第一版就犯过：滑块底座放在 y=−20，而**木栈道在 y=−300**——结果一块"栏杆"飘在海面上；
人物蹲下时加了缩放却没重算 y，脚底落到 −341，**整只陷进栈道 40 多像素**。

现在 `SceneMetrics`（Core 里）是场景基准的**唯一来源**：栈道面 y=−300、海平线 y=−140、
木船中心与尺寸、人物脚底允许的偏差。布景、人物、校验程序全读同一份数字：

| 断言 | 结果 |
|---|---|
| 所有出场人物脚底踩在栈道上 | 最深陷进 13.6 像素（上限 20）、最高悬空 0.3 像素（上限 8） |
| 三处滑块底座立在码头上（柱底扎进栈道、轨道在栈道上方、不超出画面） | 通过 |
| 六件关键道具（罗盘/刻字/海图/纸船/信/红线）停在船身范围内且可见 | 通过 |

所以**改坐标请改 `StoryData.cs` 的关键帧或 `SceneMetrics`**，然后跑一次验证命令；
"人物陷进地板""栏杆飘在天上""道具浮在船外"这类问题会被立刻报出来。

## 6. 必须在编辑器里手动确认的清单

1. 打开 `Main.unity` 按 Play → 标题画面是否有木船与三件隐约的道具、标题是否居中不叠字。
2. 点"开始" → 第一章旁白是否逐条淡入淡出，之后滑块是否解锁。
3. 找到滑块 → **能不能用鼠标顺畅拖动**、松手是否停在原地。三处大概位置（画布坐标，中心为原点）：
   - 第一章：左侧**栏杆的黄铜槽**里，约 (−520, −183)
   - 第二章：**系船桩上的旧铜环**，约 (−236, −200)——铜环挂在桩上，滑块沿横穿的旧缆绳走
   - 第三章：**工作台上的黄铜轨道**，约 (−150, −244)
4. 拖到最深处 → 罗盘是否从船底浮出、刻字"往有光的地方去。"是否清晰。
5. 点"继续" → 第二章开场时**画面是否已经比第一章淡**（跨章债务继承的可见证据）。
6. 第三章拖到最深 → 是否看到展开的信与"我一直都在。"。
7. 走完结局 → 三件道具是否同时出现在木船上、"他们都知道。"是否出现、"再走一次"是否可用。
8. 三章人物的站位、木船与码头的位置是否合理（**这是最可能需要微调的地方**）。
9. 音量是否合适（音乐 0.22 / 音效 0.55 的初始值）。

### 调画面位置改哪里

- **场景基准（栈道在哪、海平线在哪、船多大）**：`Assets/Scripts/Core/StoryData.cs` 顶部的 `SceneMetrics`。
  这是**唯一来源**，布景与校验程序都读它——只改这里，不要在各个 builder 里写死数字。
- **人物身高身宽**：同一文件里每章的 `c.Actor("Mother", 170f, 330f)`。
- **人物/道具随时怎么动**：同一文件里各章 `c.Track("...")` 的关键帧（画布坐标，1920×1080 居中）。
  人物根节点的 y 要按 `y = 栈道面 + 身高×缩放/2` 反推，脚底才会正好踩在栈道上。
- **木船随滑块起伏的潮汐**：`AddBoatTide(c, phase)`，三章用 phase 错开节拍。
- **物件本身长什么样**：`Assets/Scripts/View/DockArt.cs`。
- **滑块藏在哪、多长、底座多长**：`StoryData.cs` 里每章的 `RailCenter` / `RailWidth` / `RailPostDropFactor`。
  改了底座样式记得同步 `RailPostDropFactor`（它对应 `DockArt.BuildSliderRail` 里立柱的长度）。

改完跑一次第 1 节的验证命令。**"人物陷进地板""栏杆飘在天上""道具浮在船外"这三类问题会被第 17—19 组断言直接报出来**，
不用靠眼睛找。

## 6.6 关于"在 Unity 里直接配置场景"——试过，已撤回

有一次需求是"**在 Unity 内进行实际配置，而不是直接通过脚本生成**"。我做了一轮改造，结论是**做不了，已撤回**，
过程与原因如实记在这里，避免以后重复尝试。

### 做了什么

1. 所有对象创建改成"缺了才建、已有就用现成的"（`Ensure`）：场景里已有同名对象时一个都不重建，
   美术在 Scene 视图里挪过的位置、换过的 Sprite 就能保留；删掉某个对象也会自动补回。
2. 加了三个编辑器工具：把程序化内容**烘焙成可编辑场景**、把关键帧**导出成 ScriptableObject 资产**、
   **时间轴预览窗口**（不进 Play 模式拖时间轴看画面）。

### 为什么撤回

**烘焙出来的场景无法用于打包。** 用大场景打包后，播放器一启动就崩：

```
The file '..._Data/level0' is corrupted!  [Position out of bounds!]
```

排查过的：
- 怀疑是"指向运行期 Sprite 的引用"（程序化色块用的白图是运行时 `Sprite.Create` 出来的）——
  **把那 161 处引用全部剔除后仍然崩**；
- 最小场景（一个入口物体 + 相机）打包一直正常，反复验证过多次。

根因没定位，怀疑是 Unity 对上千个 UI 对象的场景序列化问题。
**没有拿一个跑不起来的包交付**，所以把打包改回最小场景 + 运行时生成，并撤掉了那一轮改造
（撤掉的三个文件还在 `Assets\_错过了那一秒~\_reverted\` 里，没删）。

### 撤回后的实际影响

**没有影响。** 那一轮是纯架构改动，游戏表现完全一样：撤回前后
**内核 75 组 + 运行时 43 组断言都全绿**。撤回只是让代码更直白、少三个用不上的工具。

想让美术能可视化调画面，**现在可行的办法是改 `StoryData.cs` 的关键帧坐标**（改完跑一次验证命令，
第 17—19 组断言会立刻告诉你有没有把人物放得陷进地板、把底座放到半空、把道具摆出船外）。

### 如果将来还想走这条路

两条可能绕开该问题的方向：

1. **降低对象数量**：现在一章有上千个色块对象（栏杆、栈道、船都是几十个方块拼的）。
   程序化造型换成少量对象或贴图后，烘焙场景可能就正常了。
2. **改成 Prefab**：不烘焙成场景，而是把一章生成为一个 Prefab 再实例化——序列化路径不同，可能绕开。

`_reverted/` 里那三个文件可以直接拿回来用。

## 6.7 美术与画面怎么改（现实版）

那一轮「在 Unity 里直接摆场景」的改造已经撤回（原因见 6.6），所以**改画面仍然是通过数据与代码**：

| 想改什么 | 改哪里 |
|---|---|
| 人物/道具在某个时刻的位置、旋转、缩放、透明度 | `Assets/Scripts/Core/StoryData.cs` 里对应的 `c.Track(...)` 关键帧 |
| 场景基准（栈道面、海平线、船的位置尺寸） | 同一文件顶部的 `SceneMetrics` |
| 人物身高身宽 | 同一文件里每章的 `c.Actor(...)` |
| 滑块藏在哪、多长、底座多长 | 同一文件里每章的 `RailCenter` / `RailWidth` / `RailPostDropFactor` |
| 物件本身长什么样 | `Assets/Scripts/View/DockArt.cs` |
| 用哪张美术贴图 | `Assets/Resources/Art/` 里的文件名（运行时按名字加载；删掉就自动退回程序化造型） |

改完跑一次第 1 节的验证命令。**人物陷进地板、底座飘在半空、道具浮出船外** 这三类错误会被第 17—19 组断言直接报出来，不用靠眼睛找。
