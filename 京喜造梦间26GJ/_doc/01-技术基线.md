## 1. 工程审计结论

| 项目 | 实际情况 | 对开发的影响 |
|---|---|---|
| Unity 版本 | **6000.3.8f1**（`ProjectSettings/ProjectVersion.txt`） | 手册要求"使用当前安装版本，不要擅自升级"。本机编辑器 `D:\Unity6\Editor\Unity.exe` 同为 6000.3.8，**不需要升级**。 |
| 渲染管线 | URP 17.3.0（`com.unity.render-pipelines.universal`） | 2D 游戏直接用 URP；**不新增管线包**。 |
| UGUI | `com.unity.ugui` 2.0.0 已安装 | **UI 用 UGUI**，可以全部由代码创建。 |
| TextMeshPro | **未安装** | 关键决定：**不使用 TMP**，用 UGUI `Text` + 内置 `LegacyRuntime.ttf` 字体，避免缺包/缺字体资源导致编译或运行失败。 |

| 3D / Tilemap 等模块 | 均随引擎提供 | 占位美术用 UGUI `Image` 纯色几何图形拼，**不依赖任何贴图/美术资源**。 |
| 已有脚本 | 只有 `Assets/TutorialInfo/Scripts/Readme.cs`（模板自带） | **不动它**，不改无关文件；所有游戏代码放 `Assets/Scripts/`。 |
| 现有场景 | 只有 `Assets/Scenes/SampleScene.unity`（URP 空场景） | 新建 `Assets/Scenes/Main.unity` 作为游戏入口，并把 Build Settings 场景列表指向它。 |

## 2. 目录与文件规划

```
Assets/
  Scenes/
    Main.unity              ← 游戏唯一入口场景（Build Settings 第一项），只挂一个 GameBootstrap
  Scripts/
    GameBootstrap.cs        ← 场景入口：准备摄像机 / EventSystem / GameManager
    Core/                   ← 纯逻辑层：**刻意不引用 UnityEngine**，可脱离引擎独立编译与校验
      GameState.cs          ← 枚举、MemoryTone、ChoiceLedger（只有两个整数变量）
      MemoryLevelData.cs    ← 三关的文案、选项、物件预设（数据驱动，改剧情不动流程）
      GameFlow.cs           ← 流程内核：关卡推进、倒流唯一性、变量累积、结局判定
    View/                   ← 表现层：把状态画出来
      GameManager.cs        ← 唯一总控 MonoBehaviour：输入转交 + 演出播放 + 界面刷新
      SceneBuilder.cs       ← 代码生成画布、人物、关键物件、结局与反转造型
      PlaceholderArt.cs     ← 用纯色几何图形拼占位美术（不加载任何贴图）
      UiFactory.cs          ← UGUI 工厂（按钮四态、文字、面板）
      GroupFader.cs         ← 一组 UI 元素的显隐与淡入淡出
      ClickableActor.cs     ← 人物点击 → 选中反馈
      ClickableProp.cs      ← 关键物件点击
      StageClickProxy.cs    ← 把几何造型变成可点击区域（UGUI 图元射线）
      RewindEffect.cs       ← 倒流可视化：闪屏、时间轴回退、残影、状态文字
  Editor/
    ProjectSetup.cs         ← 命令行生成入口场景 + 写 Build Settings
    EditorSelfCheck.cs      ← 播放状态下的引擎内自检
    BuildScript.cs          ← 打包 Windows 版本
  Settings/ ...             ← URP 配置，保持原样
```

**分层原则（本工程最重要的一个决定）**：`Core/` 里不放任何 `UnityEngine` 类型
（颜色用自定义的 `MemoryTone`），所以流程规则可以脱离 Unity 编译和运行 ——
这让"每关只能倒流一次""前关影响后关""三种结局可达""重新开始清零"这些规则
能在命令行里真正跑断言，而不是靠肉眼在编辑器里点。

## 3. 必须遵守的技术边界（贯穿全部阶段）

1. **不做真正的物理时间倒带**，不逐帧录制/恢复世界。全部用**预设状态切换**：
   事件后状态 / 倒流恢复状态 / 选择 A 状态 / 选择 B 状态（见 `PropState`）。
2. **每关最多一次正式回溯**（`GameFlow.RewindUsed`），重复请求一律被过滤；
   倒流只把被选中的人及其相关物件切回预设状态；
   已获得的信息、已完成的关卡、已记录的选择**不清除**。
3. **不新增第三方插件、付费素材、联网服务**；不新增 Unity 包。
4. **不要求团队手动创建大量 Inspector 引用**：场景里只有一个 GameObject，
   画布 / 按钮 / 文字 / 人物全部由代码生成。
5. **不用 TextMeshPro**（本工程未安装该包），字体用内置 `LegacyRuntime.ttf`。
6. 变量只有两个整数：`Ambition`、`Connection`，**不是善恶值**。
7. 代码必须能编译、可调试，不留伪代码 / TODO / 空方法。
8. 不做过度设计：简单状态枚举 + 少量布尔/整数变量，不建剧情引擎。

### 4.2 一条命令跑完整校验（推荐，改完代码立刻跑）

```powershell
$code = Get-Content '<工程>\_build\verify\run-verify.ps1' -Raw -Encoding UTF8
Invoke-Expression $code
```

它做三件事：
1. 用真实 `UnityEngine` 程序集**全量编译** `Assets/Scripts` 下 13 个源文件（任何语法/类型错误都会失败）；
2. 编译脱离引擎的**流程内核校验程序**；
3. 运行 23 组断言：三关流程、每关只能倒流一次、变量累积、前关影响后关、
   三种结局可达、重开本段不翻倍、重新开始清零、乱序输入防护。

> 注：脚本用 `Invoke-Expression` 执行是为了绕开本机 PowerShell 的脚本签名策略；
> 也可以先 `Set-ExecutionPolicy -Scope Process Bypass` 再直接运行。

### 4.3 关于"无头自动测试 Unity"

本工程实测：`Unity.exe -batchmode -nographics -executeMethod ... + EditorApplication.EnterPlaymode`
在 Unity 6.3 下**不会稳定推进 Play 模式**（会卡在编辑器初始化，日志停在
`Start Indexing on Editor startup` 之后）。因此把流程自动化测试放在 4.2 的独立校验程序里，
引擎内的部分由菜单「3. 播放状态下自检」补齐。这一点在阶段 6 的验收说明里也会重复强调。

### 4.4 打包

```powershell
& 'D:\Unity6\Editor\Unity.exe' -batchmode -quit -nographics `
  -projectPath '<工程>' `
  -logFile '<工程>\_build\build.log' `
  -buildTarget StandaloneWindows64 `
  -executeMethod JieNiYiMiao.EditorTools.BuildScript.BuildWindows
```
